# 회계 대조 공개 계약

2026-10-04 서버 변경에서 회계 장부를 기간 선택, 자료 상태, 요약, 상세 장부로
나누었다. 이 문서는 공개 가능한 동작과 데이터 경계만 설명하며, 실제 주문·금액·
가맹점·계좌·세금계산서 원문·외부 판매 채널 식별자는 포함하지 않는다.

## 기간과 자료 상태

회계 화면은 월별, 연간, 전체 기간을 선택한다. 선택한 기간의 자료가 실제로
들어와 있는지 다음 항목을 별도로 표시한다.

- 판매·정산 자료의 마지막 동기화 시각
- 구매팀의 전달 완료 인계 건수
- 카드 명세서와 계좌 거래내역의 해당 기간 포함 여부
- 수수료 세금계산서의 해당 기간 포함 여부

자료가 없는 기간을 0원 또는 일치로 확정하지 않는다. 커머스 자료 동기화와 문서
업로드가 늦었으면 `자료 없음` 또는 `원가 미상`으로 표시하고, 대조가 완료될 때까지
예상 수익에서 확인되지 않은 원가를 분리한다.

## 구매 인계와 원가 대조

고객 전달까지 완료된 구매 기록은 회계 장부에 멱등적으로 인계된다. 인계 1건에는
주문 가림 식별자, 판매월, 원가, 결제 통화·금액, 전달 상태와 카드 연결 상태만
공개 계약으로 노출할 수 있다.

- 같은 구매 기록을 두 번 인계하지 않는다.
- 발송 전 취소는 구매 원가가 없는지 별도로 확인한다.
- 발송 뒤 취소·반품은 이미 발생한 원가 손실과 구분한다.
- 외부 판매 채널의 이름, 주문번호, URL과 계정은 공개 화면에서 가림 처리한다.
- 카드 명세서의 실제 원화 청구액을 확인된 원가로 사용하되, 표시 원가와 차이를 보존한다.
- 자동 카드 연결은 날짜·금액 근접 후보를 제시할 뿐 확정 결정을 대신하지 않는다.
- 운영자는 자동 연결을 끊거나 카드 없음으로 확정할 수 있으며, 모든 변경은 감사 이력에 남긴다.

## 예상 수익

예상 수익은 다음 값을 분리해서 계산한다.

```text
예상 수익 = 정산액(완료 또는 예정) - 확인된 매입 원가 - 세금 예비
```

정산 전·후, 확정·진행 중, 환불·취소 손실을 나누어 표시한다. 매입 인계와 카드
명세서가 모두 없으면 원가를 추정하지 않고 `원가 미상`으로 표시한다. 과거 기간에
구매 인계가 없고 카드 명세서만 있는 경우에는 월 카드 합계를 대체 근거로 표시하되,
주문별 확정 원가로 가장하지 않는다.

## 문서함과 가져오기

회계 문서함은 카드 명세서, 계좌 입금 내역, 세금계산서, 부가세 자료와 같은 문서를
종류·귀속 기간·상태로 관리한다.

- 파일 해시로 중복 업로드를 막는다.
- 업로드 원본은 공개 저장소가 아닌 운영 보관 영역에 둔다.
- 파싱된 합계와 대조 상태만 장부 API에 반영한다.
- 원본 파일명·경로·등록자·금융기관·계좌번호는 공개 UI와 공개 API에서 제거하거나 가린다.
- 문서 상태는 받음, 정리됨, 대조 완료, 확인 필요로 구분한다.

## 공개 프런트엔드 경계

공개 `frontend/`는 다음 UI 구조와 비민감 API 계약만 제공한다.

- 통합 관제, 주문 현황, 상품 장부, 보낸 메일, 회계 장부, 계산기·정책, AI 사원,
  작업 로직 메뉴
- 기간별 회계 요약과 자료 상태 표시
- 주문 끝자리·상품 일반명·상태·가림 금액을 사용하는 목록
- 역할·팀·모델 라벨과 예약 주기 표시

다음은 공개 프런트엔드에 넣지 않는다.

- 고객 주소·이메일·주문 원문·게임 키
- 외부 판매 채널·가맹점·계정·결제 URL·주문번호
- 카드 끝자리, 계좌번호, 사업자등록번호, 세금계산서 승인번호
- 환경값·토큰·암호화 자격증명·세션·내부 IP·서버 경로
- 실제 운영 DB, 메일함, 로그, 원본 문서와 스킬 본문
